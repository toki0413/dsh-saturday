# 预注册：latent-GP 分支剪枝的任务级收益实验

- 状态：预注册（采集数据前锁定；任何偏离记入末尾“偏离日志”）
- 日期：2026-09-19
- 关联决策：`自监督学习决策：现阶段不引入…`（本实验是其“探索效率成瓶颈”触发条件的判据）；spike 前置结论（见 §11）
- 落点：为 `plugin-branch`（会话分支账本）补“分支打分器”——判断该不该给它一个 seam 位置

## 1. 问题与假设
一批从同一决策线分出的候选未来（branch/leaf），用一个 latent-GP 打分器只把有希望的叶子交给引擎真跑。相对“每支都跑引擎”，能否在固定漏检容忍下省下引擎调用。

- H1（成立→建 seam）：处理臂相对最强基线，在中位 `calls@recall90` 上省 ≥30% 引擎调用，配对检验 p<0.05，且跨体系类型方向一致。
- H0（不建）：省不到 30%，或只在部分体系赢、换体系即输，或潜变量重构残差超阈占比过高。→ latent-GP 分支剪枝不挣得 seam，回到 SSL 触发条件挂起。

## 2. 估计量与响应（主指标在分析前定死）
- 主1 `recall@B`：每战役只跑 B 次引擎时，找回的“真·最优 k 支”占比。B 取候选数的 {5%,10%,20%}。
- 主2 `calls@recall90`：达 90% recall 所需引擎调用数。头条统计 = **相对最强基线的引擎调用节省比例** =（基线 calls@recall90 − 处理 calls@recall90）/ 基线 calls@recall90，按战役计。
- 次1：分支打分序与引擎真值（回算能量/above-hull）的 Spearman ρ。
- 次2：good/bad 分支分化的 ROC-AUC（good = 真 top-k 命中集）。
- 真值来源 = 引擎回算（候选不自证，引擎是唯一 oracle）；“真·最优 k”由 Oracle 臂全跑排序确定。

## 3. 重复单元与伪重复红线
- 独立重复单元 = **战役（campaign）**：一个候选集 + 一套固定流水线 + 一个 seed + 一个体系类型。
- 一个战役内的分支决策彼此强相关，**不得把决策当 n**。所有统计在战役层级聚合，配对/区组建模。
- 每战役内 B、方法臂、指标同定义，战役间只换候选集/体系/seed。

## 4. 设计类型
within-campaign 配对（同战役跑所有臂）+ 按战役区组（区组=体系类型 × seed）。理由：跨战役方差远大于方法差，配对把体系噪声从误差项移走；不能用平行组把不同战役的分数直接比。

## 5. 方法臂（含对照，单变量隔离）
- `full`（Oracle，上界参照，非成本基线）：全支跑引擎，得 rank 与真 top-k。
- `random`（下限对照）：随机选 B 支跑。
- `persistence`（朴素基线）：分支打分=其父线最后记录值（spike 暴露：不列它会被假阳性骗）。
- `gp-energy`（竞品臂，A4 已有证据源）：LOO-GP 组成→能量，作“已有廉价代理”对照。
- **`latent-gp`（处理）**：core GP 学状态序参量一步残差转移 Δz，rollout 打分叶子。
处理臂内消融（每次只动一个因子）：`direct` vs `residual` 目标（spike 已知这决定成败）；潜变量 含/不含 热代理（KE、瞬时 T）。

## 6. 因子与干扰控制
- 因子：臂 × budget B{5,10,20%} × 体系类型{纯元素弛豫 / 掺杂 / 多组分凸包} × seed{至少 5 个}。
- 干扰：① 体系难度 → 按战役区组+配对；② 引擎成本不齐 → 主对比锁单一引擎 `lj-js`（零依赖、确定性、可复现），引擎当第二因子另做小范围敏感性；③ 候选集重叠/挑选偏倚 → 每战役候选集由 seed 生成并归档；④ 运行顺序 → 随机化，防时间/顺序漂移。

## 7. 统计分析计划（匹配设计，采集前定）
- 主检：配对 `calls@recall90`（处理 − 最强基线）跨战役 → Wilcoxon signed-rank（或配对 bootstrap CI，α=0.05，双侧）。
- 效应量：配对 Cohen's d_z（=均值差/差值标准差）+ 中位节省比例（SESOI 判据）。
- 多重比较：预算 B 三水平 + 体系三类型 → Holm 校正；确认性主检验只“latent-gp vs 最强基线”一次，余为探索。
- 失败/退化战役：引擎报错、或潜变量对已知量的重构残差 > 阈值（§8）→ 不删，按规则计为处理臂未达标并报计数（不静默挑好跑的）。
- 缺失：同战役同臂若某 run 崩，重跑一次；仍崩计该 run 处理臂 recall=0 并记数。

## 8. 样本量/功效（先 pilot 定效应，再算 N，不拍脑袋）
- 步骤1 pilot：8–12 战役、仅 lj-js、B=10%、纯元素弛豫体系 → 估配对 `calls@recall90` 差的 d_z。
- 步骤2 a-priori 功效：给定 SESOI（节省 ≥30% 折算成的 d_z 或直接差/SD）、α=0.05、power=0.80、配对设计 → 用 `power.py`（paired t / Wilcoxon）算所需战役数 N。
- 步骤3 正式量取 max(N, 覆盖 体系3×seed5 的最小格点数)。**当前不预设 N**——无任务层效应先验，硬报数即拍脑袋。

## 9. go / no-go（阈值写死，显著性只算一次）
- 判 H1 成立：pilot 定 N 后正式跑，中位节省 ≥30%（vs 最强基线）、配对 p<0.05（Holm 后）、三体系方向一致（≥2/3 体系为正）、潜变量重构残差超阈战役 ≤20%。
- 判 H0（不建 seam）：以上任一不满足，且处理臂不优于 `gp-energy` 竞品臂。→ 记入 SSL 决策“未来落点”，本线挂起。
- 判“需迭代再试”（非最终）：仅 `residual` 消融版达标、`direct` 不达标，或 含热代理才达标 → 说明形状对、潜变量/目标需保留该设定，仍不自动给 seam，需正式复跑确认。

## 10. 可复现与证据绑定
- 全链确定性：战役 seed、GP(ls/sf/noise)、候选生成 seed、运行顺序 seed 全部固定并写进结果。
- 引擎指纹：主对比恒 `lj-js`；换引擎敏感性另报 fingerprint。
- 产物：战役结果落 Trajectory（`session_fork/record`），分析脚本 + 原始 per-campaign 指标随结论归档；判据快照按仓库“判据快照与对账结论谱系登记”规范登记。

## 11. 前置 spike 结论（本设计的依据，非本实验数据）
- 直接回归 z_{t+1}：比 persistence 差 10–15×（GP 向均值收缩）→ 目标参数化是命门，故 §5 强制含 `direct` 消融。
- 残差 Δz 目标：每维打赢 persistence ~2×，10 步 rollout 相对误差 <1.3%。
- 但这是近晶格呼吸 LJ 团簇、35 转移点、纯预测层指标，量纲非任务层 → 只够立项本实验，不够建 seam。
